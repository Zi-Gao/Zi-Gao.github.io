> 主题示例文章 · 让工具服务于自己的节奏。

每隔一段时间，我都会整理一次正在使用的工具。不是寻找更复杂的替代品，而是看看有没有已经不需要的部分。

## 先问清楚问题

一个小工具好不好，首先取决于它有没有解决你真正遇到的问题。

也许你只是需要快速记下一句话，并不需要一个完整的知识管理系统；也许一个二十行的脚本，就能替代每天重复的手动操作。

## 降低开始的阻力

好的工具会让你少想一步。打开就能写，保存就能找到，出错时能看懂原因。

```js
const notes = ['今天学到的事', '还没想清楚的问题'];

for (const note of notes) {
  console.log(`留一点时间给：${note}`);
}
```

这段代码没有什么复杂功能，只是提醒自己：把需求说清楚，再决定要不要增加新的东西。

## 让工作流保留弹性

工作流是一个帮助，而不是需要严格维护的仪式。偶尔换一个方式记笔记，偶尔不整理，也并不会让之前的积累失去价值。

真正值得留下的工具，是那些你用完之后，更愿意继续做事的工具。
