> 主题示例文章 · 这里演示技术文章、代码高亮与目录的阅读效果。

独立博客最有意思的地方，是你可以决定这个空间的样子。一段文字应该在哪里换行，页面应该保留多少空白，都可以按照自己的偏好来。

## 先从内容开始

对于个人博客，文字始终是主角。这个主题把文章保存在 `src/content/blog/` 目录下，每篇文章都是一个普通的 Markdown 文件。

创建一篇文章，先写好元数据：

```yaml
---
title: '我的第一篇文章'
description: '一小段介绍，让读者知道这篇文章在说什么。'
date: 2026-10-22
category: 技术
tags: [Astro, 学习笔记]
cover: /images/digital-home.svg
draft: false
---
```

接着，在下方写正文。标题、列表、引用和代码块，都可以用熟悉的 Markdown 语法表达。

## 让结构保持简单

博客不必一开始就拥有所有功能。先保证三件事：

1. 文章能被舒服地阅读。
2. 旧文章可以被方便地找到。
3. 新内容能以很低的成本写下。

技术选型应该服务于这三件事，而不是让写作变成另一项复杂工程。

### 内容与外观分开

在这个项目中，站点信息放在 `src/site.config.ts`，全局样式放在 `src/styles/global.css`。修改站名，不需要翻阅每一个页面；调整颜色，也只需要修改几个 CSS 变量。

```css
:root {
  --paper: #ffffff;
  --ink: #282a27;
  --accent: #b85c3c;
}
```

## 写完，再往前走一步

本地预览时，先运行开发服务器：

```bash
npm run dev
```

准备生成静态站点时：

```bash
npm run check
npm run build
```

生成的 `dist/` 目录就是最终的静态站点。发布之前，记得把 `.env` 中的 `SITE_URL` 换成自己的域名，这样 RSS 和站点地图才会指向正确的地址。

## 小屋的意义

一个博客不需要先被很多人看见，才值得存在。它首先是自己的思考档案，是过去某个瞬间认真生活过的证据。

搭好小屋之后，记得回来住。写下一点东西，就是给它添一盏灯。
